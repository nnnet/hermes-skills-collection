# Data Governance Metadata Schema

**MANDATORY** for every document/record across all projects and storage backends (Chroma, Wiki, databases, files).

## Layers

### 1. Provenance (Non-negotiable)
- `source_url` — origin of the content
- `source_type` — enum: `youtube_video`, `pdf`, `github_repo`, `vk_post`, `website`, `drive_doc`, `article`, `paper`
- `source_created_date` — ISO 8601 date when the **original** content was created (upload date, commit date, post date). Distinct from `processed_date`.
### 1. Provenance (Non-negotiable)
- `source_url` — origin of the content
- `source_type` — enum: `youtube_video`, `pdf`, `github_repo`, `vk_post`, `website`, `drive_doc`, `article`, `podcast`
- `source_created_date` — when the original was created (upload date, commit date, post date)
- `author` — content author (lecturer, writer, presenter)
- `participants` — list of speakers/co-authors in the content (important for videos with multiple speakers)
- `processor_agent` — which agent processed it
- `processed_date` — ISO 8601 timestamp
- `primary_review_status` — passed/warning/rejected/pending
- `reviewed_by_agent` — which agent approved it
- `approval_chain` — audit trail of who approved when

### 2. Semantic (Haiku LLM generates)
- `hashtags` — auto-generated tags for discovery (#quantitative-finance, etc.). Generate 3-8 per chunk: enough for different search angles but not excessive. Include both specific (#ito-lemma) and general (#finance) tags. Auto-generated by Haiku from title + content + key_concepts.
- `key_concepts` — extracted main ideas (list)
- `summary` — 1–2 sentence quick summary
- `domains` — list of applicable domains (one document can span multiple: finance + mathematics + ML)
- `subdomain` — specific focus area

### 3. Quality & Validation
- `confidence_score` — 0.0–1.0, how certain is the processing
- `completeness_score` — 0.0–1.0, how complete is the source material
- `validation_status` — passed/warning/failed
- `quality_notes` — what issues exist, if any

### 4. Connectivity
- `related_documents` — doc IDs of similar/related entries (from vector similarity)
- `depends_on` — doc IDs that must be understood first
- `version` — v1, v2, etc. if document evolves
- `project_id` — CMF-YNVRSTY, ML-Labs, etc.

### 5. Technical
- `content_hash` — SHA256 for deduplication
- `language` — ISO 639-1 code (en, ru, zh, etc.)
- `processing_config` — JSON: model, parameters, settings used
- `embedding_vector` — save embedding for semantic search (Chroma)

## Validation Rules

Before ANY write operation (add_documents, Wiki page create, database insert):
Before ANY write operation (add_documents, Wiki page create, database insert):
1. Check all Layer 1 (Provenance) fields exist and are non-empty
2. Check `domains` is a non-empty list (not a single string)
3. Check `hashtags` is a non-empty list with 3-8 entries
4. If Layer 1 fails: **block the operation**
5. Layers 2–5 can be auto-filled by Haiku or defaults, but Layer 1 is hard requirement

## Haiku Service Tasks

Use the small LLM (Haiku) for:
- Generate hashtags from title + summary
- Extract key_concepts via NLP
- Auto-fill summary from full content
- Compute similarity scores for related_documents
- Assess completeness_score via heuristics
- Flag quality_notes (missing info, contradictions, etc.)
